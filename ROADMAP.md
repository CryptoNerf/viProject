# Roadmap

План развития viProject после аудита (октябрь 2026). Пункты внутри разделов отсортированы по приоритету.

Отмеченные пункты (`[x]`) уже сделаны: раскладки phone / tablet / desktop выбираются автоматически
(см. `computeLayout()` в `public/index.html` и CSS-блок «АДАПТИВНЫЕ РАСКЛАДКИ»).

## 1. Распознавание жестов

- [x] **Загрузка без CDN и с прогрессом**: все файлы MediaPipe (включая `hands.js` / `face_mesh.js`)
  лежат в `public/mediapipe`, модели скачиваются с реальным прогрессом (карточка с процентами и МБ),
  при сбое — сообщение и кнопка Retry, при медленной сети — предупреждение. Модель лица грузится
  только после рук. Приложение работает мышью/касаниями, пока модель загружается.
- [x] **Распознавание только новых кадров камеры** (раньше нейросеть запускалась 60 раз/с на камеру
  20–30 кадров/с), лицо — ~10 раз/с, без уточнения радужки (`refineLandmarks: false`, вдвое быстрее).
- [x] **Переключение камеры** (фронтальная ↔ основная на телефонах/планшетах, перебор камер на компьютере).
- [x] **Плавное движение рук**: фильтр One Euro + продолжение движения между кадрами распознавания.
  Раньше на телефонах/iPad (10–20 распознаваний в секунду) курсор руки 3 кадра из 4 стоял на месте и прыгал.
  Частота распознавания на мобильных подстраивается под скорость устройства (15–30 раз/с), камера — 640×480.
- [ ] Облегчённая модель руки (`modelComplexity: 0`, файл `hand_landmark_lite.tflite`) для слабых телефонов:
  примерно вдвое быстрее, чуть менее точная. Включать автоматически, если распознавание дольше ~40 мс.
- [ ] **MediaPipe Tasks Vision** (`@mediapipe/tasks-vision` 1.0.1) — **решено пока не переходить**.

  Замеры (октябрь 2026, Chrome, Apple M5; та же картинка 640×480, медиана на кадр):

  | | Руки, кадр | Инициализация | Загрузка до «руки готовы» (brotli) |
  | --- | --- | --- | --- |
  | `@mediapipe/hands` 0.4 (текущий) | 8.9–17 мс | 0.3 с | ~9.4 МБ |
  | Tasks Vision, GPU | 9.5–18 мс | 0.2–1.2 с | ~9.2 МБ |
  | Tasks Vision, CPU | 31 мс (113 мс при CPU ×4) | 0.2 с | ~9.2 МБ |

  Старый движок уже считает нейросеть на видеокарте (WebGL), поэтому ускорения переезд не даёт,
  а объём загрузки почти тот же. Оба движка нельзя держать на одной странице (конфликт глобального
  `Module` у WASM-загрузчиков), то есть переход — только целиком.

  **Когда вернуться к вопросу:** если старый движок перестанет работать в новых версиях браузеров
  (он не обновляется с 2023 года), если понадобится надёжное определение открытого рта (у Tasks есть
  готовый blendshape `jawOpen`, не зависящий от расстояния до камеры) или распознавание в Web Worker.
  Объём работы: заменить загрузчик (`startHandsEngine`/`startFaceEngine`) и адаптер результатов —
  формат 21 точки руки тот же, логика жестов не меняется; затем проверить на реальных устройствах.
- [ ] **Нормировать пороги жестов по размеру ладони** (расстояние запястье → основание среднего пальца).
  Сейчас пороги заданы в абсолютных координатах кадра, поэтому распознавание зависит от расстояния до камеры.
- [ ] **Нормировать порог открытого рта по высоте лица** — по той же причине.
- [ ] Экран калибровки: пользователь показывает ладонь, приложение подстраивает пороги под руку и камеру.

## 2. Производительность и качество картинки

- [ ] **Считать поле метаболов в WebGL-шейдере** (или в Web Worker через `OffscreenCanvas`).
  Сейчас поле считается на CPU в главном потоке — это основная нагрузка кадра.
- [ ] **Чёткий рендер на Retina/HiDPI**: холст с учётом `devicePixelRatio`. Без пункта выше это
  в 2–4 раза дороже, поэтому делать вместе с WebGL или только для контуров.
- [ ] Не обрабатывать каждый кадр камеры, если рука не двигается (пропуск кадров при простое).

## 3. Код и инфраструктура

- [ ] **Разбить `public/index.html` (~6700 строк)** на `css/app.css` и ES-модули без сборщика:
  `render.js` (метаболы, marching squares), `gestures.js`, `input.js` (мышь/тач/клавиатура),
  `editor.js` (заливка, карандаш, ластик), `history.js` (undo/redo), `ui.js`.
- [ ] Перенести smoke-тест (puppeteer + фейковая камера) в репозиторий и запускать в CI (GitHub Actions).
- [ ] Заголовки кеширования в `vercel.json` для `/mediapipe/*` (файлы большие и меняются редко).
- [ ] Удалить неиспользуемую корневую папку `fonts/` (шрифт берётся из `public/fonts`).
- [ ] Убрать `.claude/settings.local.json` из репозитория: `git rm --cached .claude/settings.local.json`.

## 4. Функции и удобство

- [x] При входе в режим редактора сразу включается инструмент рисования (заливка или последний
  использованный), строка статуса подсказывает, что делать выбранным инструментом.
- [x] Разовые подсказки в ключевые моменты (первый вход в редактор, касание пустого места инструментом Select).
- [ ] Короткий интерактивный тур при первом запуске (3–4 шага: жесты, инструменты, редактор, экспорт).
- [x] Подписи под иконками панели инструментов на десктопе/планшете (иконки нарисованы от руки и не всегда очевидны).
- [x] Переключатель режима **Gestures | Editor** вверху вместо индикатора, похожего на кнопку, и двух разных кнопок режима.
- [x] Шапка у панелей настроек и палитры (заголовок + крестик в одной строке, на телефоне/планшете прилипает при прокрутке);
  настройки разбиты на группы, палитра показывает только секции выбранного инструмента.
- [x] Lock/Unlock неактивны без выделенной молекулы; подсказка на пустом холсте.
- [ ] Перерисовать иконки в едином стиле (сейчас «Create» — фигурка-крест, «Select» — рука с жестом) и добавить
  иконку-подсказку к каждому разделу мануала.
- [ ] Подсказки к кнопкам на телефоне по долгому нажатию (на сенсорном экране нет `title` при наведении).
- [ ] Палитра: последние использованные цвета; запоминать позицию палитры на десктопе.

- [ ] **Сохранение и загрузка работ** (файл `.json`) и автосохранение в `localStorage`.
- [ ] Экспорт в SVG (контуры marching squares уже есть — их можно сохранить как пути).
- [ ] Выбор длительности записи видео (сейчас фиксировано 30 секунд).
- [ ] Пипетка (взять цвет с холста).

## 5. Доступность

- [ ] Кнопки-`div` (`?`, `≡`, `▼`) заменить на `<button>` — сейчас они недоступны с клавиатуры.
- [ ] Видимый фокус и подписи `aria-label` у кнопок с иконками.
- [ ] Не запрещать масштабирование страницы (`user-scalable=no`) вне холста.

## 6. Версия для телефона

Сейчас мобильная версия — это десктопная с уменьшенными элементами. Что нужно доработать:

- [x] **Нижняя панель инструментов** (как в мобильных редакторах): Select / Create / Delete /
  Lock / режим редактора — одной строкой у нижнего края, под большой палец. Левая вертикальная панель
  на узком экране закрывает холст.
- [x] **Настройки и палитра — выезжающие снизу листы** (bottom sheet) с «ручкой», а не плавающие окна.
  Одновременно открыт только один лист.
- [x] **Портретная и альбомная ориентация**: убрать `"orientation": "portrait"` из `manifest.json`
  и проверить раскладку в альбомной (камера телефона чаще удобнее горизонтально).
- [x] **Безопасные зоны**: отступы через `env(safe-area-inset-*)` под вырез и полоску «домой» на iPhone.
- [x] **Высота экрана**: `100dvh` вместо `100vh`, чтобы адресная строка не перекрывала нижние кнопки.
- [x] **Поворот молекулы двумя пальцами** (как Alt+мышь).
- [x] Касание пустого места создаёт молекулу только инструментом Create (Select — выделение и перемещение).
- [ ] Двойной тап — выделить/снять выделение, тап двумя пальцами — отмена.
- [x] **Кнопки Undo / Redo** на экране (на телефоне нет клавиатуры для Ctrl+Z).
- [x] **Режим экономии энергии**: понижать частоту распознавания рук до 15 FPS и отключать FaceMesh,
  когда режим редактирования ртом не используется.
- [ ] Предупреждение при перегреве/низком FPS с предложением отключить камеру (режим «только касания»).
- [x] Минимальный размер всех нажимаемых элементов 44×44 px (сейчас часть иконок палитры 20×20).

## 7. Версия для планшета

Планшет (iPad, Android-планшеты, 768–1366 px) сейчас попадает то в мобильную, то в десктопную раскладку.

- [x] **Отдельный брейкпоинт 768–1180 px**: панель инструментов слева (как на десктопе), но с крупными
  кнопками; палитра — закреплённая боковая панель справа вместо плавающего окна.
- [x] **Поддержка Apple Pencil / стилуса** через Pointer Events: перо рисует линии с толщиной по силе
  нажатия (с заливкой: тап — залить, ведение — рисовать), касания ладонью рядом с пером игнорируются.
- [ ] **Перевести мышь и тач на Pointer Events** (стилус уже на Pointer Events) — один код вместо двух
  (заодно корректная работа на ноутбуках с сенсорным экраном).
- [x] **Режим «камера + касания» одновременно**: планшет на подставке — жесты одной рукой,
  правка пальцем по экрану.
- [x] Поддержка внешней клавиатуры (Magic Keyboard): все сочетания `Cmd`, подсказки по ним в меню.
- [x] Split View / Slide Over на iPad: корректная перерисовка при изменении ширины окна.
- [x] Альбомная ориентация как основная, книга-мануал — разворотом на весь экран.
